# Voice mode ("walkie-talkie") — implementation plan

Historical plan for the mobile voice feature. Branch `mobile/voice`
(from `mobile/integration`). Mobile only; the desktop is untouched apart from
the shared proto crate and the hook binary it already ships.

## 1. Context and decisions

Talk to a coding agent from the phone like a walkie-talkie: pick an agent,
enter voice mode, hold a button and speak. The utterance goes to the host, is
transcribed locally with NVIDIA Parakeet Unified EN 0.6B (Q8), and is typed into
the agent's tmux pane with Enter. When the agent's turn ends, its final message
is synthesized with Microsoft Edge TTS and auto-played on the phone.

Decisions made during planning:

- **STT runs in a Python sidecar the host spawns with `uv`** (`transcribe-cpp`
  and its native-provider wheel). Not in-process Rust: that would put the hot
  model and native inference runtime inside the daemon that serves every
  terminal, grow the host binary for every user, and add native build inputs to
  the digest-cached release pipeline. Not a user-run server either. Hard
  dependency: `uv` on the host.
- **Sidecar exits after 5 minutes idle**; respawned on demand. The model
  stays hot in between (a 10 s utterance transcribes in well under a second).
- **TTS = edge-tts only** in v1, in the same sidecar. The wire keeps a
  `provider` field so ElevenLabs (key kept on the host as an env var / config
  file, never on the phone) can be added later without protocol churn.
- **The latest reply is a voice message, Telegram-style.** A reply
  auto-plays when it arrives while the Voice screen is in the foreground, and
  the newest reply keeps play / pause / stop and a seekable position bar so
  you can hear it again if you missed something. Only the newest reply's MP3
  is kept; when the next reply arrives the previous file is deleted and the
  older message remains as text in the list. The session (text history and
  the latest MP3) lives until you explicitly end it: it survives navigating
  away and backgrounding the app (going to a meeting and coming back).
  Nothing persists across app restarts in v1.
- **Background**: while the app is backgrounded the session stays registered
  and pushed replies are stored as unplayed messages; nothing auto-plays in
  the background. Returning to the screen auto-plays the newest unplayed
  message.
- **Reply source**: the `Stop` hook's `last_assistant_message`, pushed to the
  phone, nothing kept on the host. The alternative considered is reading the
  agent's on-disk transcript at `Stop` (Claude Code and Codex both keep
  JSONL; `apps/host/src/hook/codex_transcript.rs` already reads Codex's
  safely). Not used in v1 because Claude's docs say the transcript file lags
  the hook, and the hook field is exactly the final text. It stays the
  fallback if a vendor ever drops the field.
- **Multiple agents later.** A future state is several voice sessions at
  once (three big coloured buttons, one per agent, talk to each in turn).
  v1 shows one agent per screen, but the wire and the phone store are keyed
  by `agent_id` and hold N sessions, so that screen is additive.
- **Agent reply text comes from the `Stop` hook's `last_assistant_message`**,
  which both Claude Code and Codex send. No screen scraping: the codebase
  removed it deliberately (`AgentRecord` reserved field 7 comment).
- **Push, not store.** The phone registers a voice session for one agent; on
  that agent's `Stop` the host synthesizes the reply and pushes text + MP3 to
  that connection in one event, then keeps nothing. No per-agent reply store,
  nothing on disk, nothing retained for agents without a voice session. A
  daemon restart costs at most the one reply in flight.
- **Pre-warm, minimal**: STATUS carries `warm = true` when the Voice screen
  opens; if READY, the host spawns the sidecar and loads the model in a
  detached task. One flag, one task; no press-in variant.
- **Not in v1, deliberately**: streaming transcription (needs a streaming
  model and chunked upload; the right follow-up for live captions).
- Wire change lands on host + mobile in one branch (CLAUDE.md: no
  compatibility arms). Desktop only recompiles the proto; it ignores the new
  operations.
- Audio crosses the wire as one `Request.data` payload (no chunking): a
  30 s mono 16 kHz AAC utterance is ~200 KB against a 16 MiB frame limit.
  Host rejects audio over 8 MiB.

## 2. Facts the plan relies on

- Mobile: Expo SDK 57 / RN 0.86, expo-router, zustand, Android-only. No audio
  deps or `RECORD_AUDIO` permission yet. Config of record is
  `apps/mobile/app.json`; `android/` is regenerated by prebuild.
- Transport: one SSH exec channel running `muxflow-host bridge --stdio`;
  length-prefixed protobuf `Envelope`; `MAX_FRAME_BYTES` 16 MiB. Requests are
  built in `apps/mobile/src/protocol/requests.ts`, sent by
  `HostConnection.request(req, { timeoutMs })` (default 20 s). A bulk lane
  exists (`openBulkConnection` in `apps/mobile/src/session/connectionManager.ts`,
  used by the file viewer).
- Typing into a pane: `terminalInput(paneId, bytes)` → `OPERATION_TERMINAL_INPUT`
  (`Request.scope` = pane id, `Request.data` = bytes); the UI appends `CR`
  from `apps/mobile/src/features/terminal/chips.ts`. The host adds no
  bracketed paste and no Enter (`apps/host/src/service/terminal/input.rs`), so
  a transcript must be a single line.
- Agent state arrives as `EVENT_KIND_AGENT_STATE`; `HostConnection` calls
  `options.onAgentTransition({ prev, next })` (used today by notifications).
  That is the auto-play trigger.
- Host: Rust, tokio + prost, no HTTP client, no config file (env vars only).
  Spawns tmux/git/tar from PATH; tmux discovery in
  `crates/tmux-control/src/executable.rs::tmux_executable()` (env override →
  PATH → known candidates) is the pattern for finding `uv`. Request admission
  rows live in `apps/host/src/service/requests/operation_policy.rs`, dispatch
  arms in `apps/host/src/service/requests/dispatcher.rs`.
- Hook binary (`apps/host/src/hook.rs::run`) whitelists vendor JSON into a
  normalized map (≤ 256 KiB, `MAX_NORMALIZED_HOOK_BYTES`) before forwarding
  `AgentHookEvent.payload_json` to the daemon; ingest in
  `apps/host/src/service/agents/ingest.rs` (Stop handling), per-agent state in
  `apps/host/src/service/agents/store.rs`.
- expo-audio on Android records AAC in `.m4a` only (no PCM/WAV/Opus).
  expo-file-system `new File(uri).bytes()` reads the recording;
  `new File(Paths.cache, name).write(Uint8Array)` stores the returned MP3.
- Model: `parakeet-unified-en-0.6b-Q8_0.gguf` (731,357,568 bytes) from the
  revision-pinned Handy conversion of `nvidia/parakeet-unified-en-0.6b`.
  Python: `transcribe_cpp.Model(path, backend="auto")`, a persistent session,
  then `session.run(pcm, language="en", timestamps="none")`. The Rust audio
  layer supplies mono 16 kHz f32 PCM. `edge_tts.
  Communicate(text, voice).stream()` yields MP3 chunks.
- Release gate: Handy's pinned catalog labels the conversion CC-BY-4.0, while
  NVIDIA's current base-model card names the NVIDIA Open Model License. Resolve
  that metadata mismatch and ship the governing license/attribution before
  releasing this downloader; the implementation pin alone does not settle it.

## 2b. Performance budgets (we care; the app must stay fast and lean)

Targets on a LAN, 4-core x86 host, mid-range Android phone. Each is measured
in wave 3 and recorded in `docs/mobile/qa.md`.

| Path | Budget | How the design meets it |
| --- | --- | --- |
| Press-in → recording indicator | < 100 ms | `prepareToRecordAsync()` runs when the Voice screen opens, not on press. Press only calls `record()`. |
| Release → transcript on screen (warm, ≤ 10 s speech) | ≤ 1.5 s | 16 kHz mono AAC at 48 kbps is ~6 KB/s (60 KB per 10 s: ~2 SSH write chunks); symphonia decode and PCM transfer stay small; Unified Q8 runs with `num_threads = min(4, cpus)`. |
| Release → text lands in the pane | ≤ 2.5 s | Phone chains `TERMINAL_INPUT` immediately after the transcript; no host-side typing hop. |
| Cold sidecar (first use after 5 min idle) | hidden behind screen open; worst case ≤ 12 s with a visible "warming up" state | STATUS `warm` on screen open loads the model while the user reads the screen and presses; a session is back-and-forth, so it stays hot afterwards. |
| Agent `Stop` → reply audio starts | ≤ 2.5 s | The host synthesizes on `Stop` and pushes text + MP3 to the voice-active connection; the phone does one file write and plays. No request round trip. |
| Reply payload | ≤ 4 MiB hard cap, ~600 KB typical | 1,500-char cap ≈ 100 s of 48 kbps MP3. The SSH → JS bridge base64-decodes events in JS (`src/ssh/base64.ts`), so this cap keeps decode under ~50 ms, the same reason the file viewer caps at 2 MiB. |
| Sidecar memory | ≤ 2 GB RSS hot, 0 after 5 min idle | Idle unload; `PR_SET_PDEATHSIG` so no orphan survives a daemon crash. |
| Host binary and RSS | binary +< 1 MB, RSS +< 5 MB | Symphonia and the pure-Rust resampler stay in-process; the native inference runtime and HTTP client remain in the sidecar. |
| APK | +≤ 3 MB | `expo-audio` and `expo-file-system` only; no JS audio or markdown libraries. |
| UI re-renders | none per progress tick beyond the progress bar | Sidecar emits progress ≥ 250 ms apart; the screen selects narrow store slices; turn list is a plain `ScrollView` (tens of items). |

Instrumentation: the host logs `decode_millis`, sidecar round-trip and queue
wait per voice request under the existing perf-log pattern in
`apps/host/src/diagnostics.rs`; the phone logs per-phase durations
(record, upload, transcribe, input, speak, play) through `src/session/log.ts`
so they show in the log viewer. `VoiceTranscript.audio_millis` /
`decode_millis` are on the wire for that purpose.

### 2c. Zero cost when unused, and before/after regression checks

Voice must not slow down or fatten anything for a user who never opens it.

- Nothing voice-related runs until the Voice screen is opened: no sidecar, no
  timers, no cache dir, no extra store subscriptions. `VoiceService::global()`
  is created lazily on the first voice request. The agent-transition fan-out
  gains one subscriber only while a Voice screen is mounted.
- The hook path gains one optional field on `Stop` (≤ 32 KiB, usually a few
  KB), consumed by ingest and never stored; every other event is untouched.
- The host gains pure-Rust decode/resample crates (symphonia and rubato); no
  background threads.
- The phone gains two Expo modules and one route; nothing is imported on the
  Agents or Terminal screens except the mic glyph's `router.push`.

Measured before wave 1 on `mobile/integration` and after wave 3 on
`mobile/voice`, same host and phone, recorded side by side in `docs/mobile/qa.md`:

| Metric | How |
| --- | --- |
| Host binary size | `ls -l target/release/muxflow-host` |
| Host daemon RSS idle and with one attached terminal | `ps -o rss -p $(pgrep -f 'muxflow-host daemon')` |
| Hook round trip (`Stop` → AGENT_STATE on the phone) | existing `tests/integration/agents` timings + phone log timestamps |
| Terminal input echo latency while a transcription is running | `pnpm test:performance` stall probe plus a manual keystroke timing with the sidecar busy |
| Connect → Agents list populated | phone log timestamps |
| APK size | `ls -l` on the debug APK from `pnpm mobile:apk` |
| App cold start to Agents tab | `adb shell am start -W` |
| JS thread frame drops while the Voice screen shows progress | React DevTools / `adb shell dumpsys gfxinfo` |

Acceptance: no metric above regresses beyond noise (binary +< 1 MB, RSS +< 5 MB,
APK +≤ 3 MB, latencies unchanged). The voice-path budgets in §2b are measured
in the same session.

## 3. Part A — Protocol (`crates/protocol`, mirrored in mobile)

`crates/protocol/proto/envelope.proto` (append-only; keep `TEST_*` at 100+):

```proto
enum Operation {
  // ...existing, last real value OPERATION_REQUEST_TERMINAL_HISTORY = 48
  OPERATION_VOICE_STATUS = 49;      // readiness probe; never spawns anything
  OPERATION_VOICE_PROVISION = 50;   // consent-gated 697 MiB download; progress by event
  OPERATION_VOICE_TRANSCRIBE = 51;  // audio bytes -> one-line transcript
  OPERATION_VOICE_SPEAK = 52;       // text -> mp3 bytes (replay, arbitrary text)
  OPERATION_VOICE_SESSION = 53;     // register/clear the agent whose replies this connection wants pushed
}

message Request   { /* ... */ VoiceRequest voice = 19; }   // next free after 18
message Response  { /* ... */ VoiceResponse voice = 13; }
message HostEvent { /* ... */ VoiceEvent voice = 13; }
enum EventKind    { /* ... */ EVENT_KIND_VOICE_PROVISION = 20; EVENT_KIND_VOICE_REPLY = 21; }

enum VoiceProvider { VOICE_PROVIDER_UNSPECIFIED = 0; VOICE_PROVIDER_EDGE_TTS = 1; } // ElevenLabs later

enum VoiceReadiness {
  VOICE_READINESS_UNSPECIFIED = 0;
  VOICE_READINESS_UV_MISSING = 1;     // detail carries the install hint
  VOICE_READINESS_MODEL_MISSING = 2;  // uv found; provision needed
  VOICE_READINESS_PROVISIONING = 3;   // provision carries progress
  VOICE_READINESS_READY = 4;
}

message VoiceRequest {
  string operation_id = 1;              // client correlation, echoed back
  bytes audio = 2;                      // TRANSCRIBE
  string audio_mime = 3;                // audio/mp4 (expo-audio); also audio/x-m4a, audio/aac
  reserved 4;
  string text = 5;                      // SPEAK: text to synthesize (replay / arbitrary text)
  string agent_id = 6;                  // SESSION: agent whose replies this connection wants spoken ("" = stop)
  VoiceProvider provider = 8;           // unspecified = EDGE_TTS
  string voice = 9;                     // "en-US-AvaNeural" default; validated identifier
  bool confirmed = 10;                  // PROVISION: consent to the download; refused without it
  bool warm = 11;                       // STATUS: if READY, spawn + load the sidecar in a detached task
}

message VoiceProvisionProgress {
  string operation_id = 1;
  string phase = 2;                     // installing_runtime | downloading | verifying | ready | failed
  uint64 transferred_bytes = 3;
  uint64 total_bytes = 4;               // 0 while unknown (uv's own install has no byte count)
  string error = 5;
}

message VoiceStatus {
  VoiceReadiness readiness = 1;
  string uv_path = 2;
  string model_dir = 3;
  uint64 model_download_bytes = 4;      // for the consent copy (697 MiB)
  string detail = 5;                    // install hint when UV_MISSING; last sidecar error otherwise
  bool sidecar_running = 6;             // model currently hot
  VoiceProvisionProgress provision = 7; // set while PROVISIONING so a reconnecting phone resumes the bar
}

message VoiceTranscript { string text = 1; uint32 audio_millis = 2; uint32 decode_millis = 3; }

message VoiceSpeech {
  bytes audio = 1;                      // audio/mpeg
  string audio_mime = 2;
  string display_markdown = 3;          // original text shown by the phone
  bool truncated = 4;
  string voice = 5;
  VoiceProvider provider = 6;
  string agent_id = 7;                  // echoed when the reply came from the store
  uint64 state_generation = 8;
  int64 reply_at_unix_millis = 9;
  string speech_text = 10;              // exactly what was synthesized (flattened / capped)
}

message VoiceResponse {
  string operation_id = 1;
  VoiceStatus status = 2;               // STATUS / PROVISION
  VoiceTranscript transcript = 3;       // TRANSCRIBE
  VoiceSpeech speech = 4;               // SPEAK
  bool retryable = 5;                   // set on error responses (Response has no retryable field)
}

message VoiceEvent { VoiceProvisionProgress provision = 1; VoiceStatus status = 2; VoiceSpeech reply = 3; }  // reply: EVENT_KIND_VOICE_REPLY
```

- **Capability**: `CAP_VOICE = 1 << 18` in `crates/protocol/src/lib.rs` (bit 17 is
  already `CAP_TMUX_EXECUTABLE_RESOLUTION`); add to `HOST_CAPABILITIES`, grow
  `CAPABILITY_NAMES` to 19. Mobile `contract.ts` currently stops at bit 16: add
  bit 17 (`tmuxExecutableResolution`) and bit 18 (`voice`), fix the "bits 0..16"
  comments, and move any `0x1FFFF` assertion in `HostConnection.test.ts` to
  `0x7FFFF`.
- **Lane**: all on `Lane::Control`. STATUS and SESSION are `(ReadOnly, Control, Inline)`;
  PROVISION / TRANSCRIBE / SPEAK are `(Mutation, Control, Detached)` — they
  spawn a process and write the cache dir, must not hold the reader loop, and a
  read-only host must not start downloading. Audio rides as one payload
  (30 s AAC ≈ 250 KB in, MP3 ≈ 300 KB out, ~2 % of `MAX_FRAME_BYTES`); input
  is capped at 8 MiB and output at 4 MiB (see §2b). The bulk lane needs a bound connection and
  is for file bodies; a voice exchange is a one-shot whose `Cancel` should
  arrive on the same connection. If head-of-line blocking of terminal output
  is ever measured, flip the lane to `Either`; nothing else changes.
- Error responses use the existing `response_error(code, msg)` plus
  `voice: VoiceResponse { operation_id, retryable }`. Codes in §4.6.
- `crates/protocol/tests/roundtrip.rs`: `voice_operations_and_payloads_are_append_only`
  pinning the four numbers, plus encode/decode of the three voice messages.
- Mobile mirror: `pnpm --filter @muxflow/mobile protocol:gen`; `requests.ts`
  builders `voiceStatus(opId)`, `voiceProvision(opId)` (sets `confirmed`),
  `voiceTranscribe(opId, audio, mime)`, `voiceSpeak(opId, text, voice?)`,
  `voiceSession(agentId | "")`; `HostConnection` routes
  `EVENT_KIND_VOICE_PROVISION` and `EVENT_KIND_VOICE_REPLY` to an
  `onVoiceEvent` option next to `onFileEvent`.

### 4.2 Sidecar contract

Spawn: `uv run --python 3.12 --no-project --no-config --with transcribe-cpp==<PIN>
--with edge-tts==<PIN> <cache>/voice/sidecar-<hash>.py`, `current_dir(cache)`,
`PYTHONUNBUFFERED=1`, `kill_on_drop(true)`, Linux `pre_exec(prctl(PR_SET_PDEATHSIG,
SIGTERM))` so a crashed daemon cannot orphan a 1 GB-resident child. Pins are
`const`s in `sidecar.rs`; resolve current versions when implementing.

Framing: one JSON header line, optionally followed by exactly `body_bytes` raw
bytes. Both directions. No base64, no temp files.

```
-> {"id":1,"op":"load"}
<- {"id":1,"ok":true,"load_millis":4210}
-> {"id":2,"op":"transcribe","sample_rate":16000,"body_bytes":640000}   + f32 LE PCM
<- {"id":2,"ok":true,"text":"list the files in this directory","decode_millis":812}
-> {"id":3,"op":"speak","text":"...","voice":"en-US-AvaNeural"}
<- {"id":3,"ok":true,"mime":"audio/mpeg","body_bytes":301122}           + mp3
-> {"id":4,"op":"provision","model_dir":"...","url":"..."}
<- {"id":4,"event":"progress","phase":"downloading","transferred":1048576,"total":671088640}  (>= 250 ms apart)
<- {"id":4,"ok":true}
-> {"op":"cancel","id":4}
<- {"id":N,"ok":false,"class":"network|model|input|internal","error":"..."}
```

`sidecar.py`: `sys.stdin.buffer` loop; `transcribe_cpp.Model(..., backend="auto")`
and `model.session(n_threads=min(4, os.cpu_count()))` created lazily on `load`;
offline English `session.run()` over the request's mono 16 kHz f32 body;
`edge_tts.Communicate(text, voice).stream()` concatenating audio chunks;
provision via `urllib.request.urlopen` into `<models>/.partial-<pid>.gguf`
with a `threading.Event` for cancel, streamed SHA-256 and byte-count checks,
atomic file/marker replacement, and fsync before success.
Network exceptions map to `class:"network"`.

### 4.3 VoiceService behaviour

- **Serialization**: a `tokio::sync::Mutex<Slot>` gives one in-flight sidecar
  request; more than 4 waiters → `voice_busy` (retryable).
- **Warm-up**: the first request after spawn sends `load` and waits up to
  120 s (cold `uv run` may still be resolving wheels; encoder load 3–10 s).
  Warm timeouts: transcribe `30 s + 2 × audio duration`, speak
  `20 s + 10 ms/char`.
- **Idle unload**: `last_used` updated per request; a companion task checks
  every 30 s and, when ≥ 300 s idle (`MUXFLOW_VOICE_IDLE_SECS` override) and
  the mutex is free, `start_kill()` + `wait()`. Respawn is lazy.
- **Voice sessions**: `sessions: Mutex<HashMap<agent_id, Session { connection, since }>>`,
  bounded to 8 entries, 10-min TTL refreshed by the phone's periodic SESSION
  (every 5 min while the screen is open), dropped when the connection closes
  or the phone sends `agent_id = ""`. `on_agent_reply` ignores agents with no
  session, so nothing is retained for them. For a session agent it runs
  `speech_text` + sidecar `speak` on a detached task (behind any user
  request) and pushes `HostEvent { kind: VOICE_REPLY, voice.reply }` to that
  connection via the events fan-out; the MP3 is dropped after the send.
  When one hook event replaces pane-derived agent IDs with a native ID, ingest
  moves the newest retired registration to the native ID after persisting the
  agent state and before dispatching a Stop reply. An existing native-ID
  registration wins after expired/dead registrations are pruned; connection
  ownership and the original TTL timestamp are preserved. Only empty-native-ID
  registrations can move to a non-empty native identity. The transfer only
  touches this bounded map and never creates the service or starts the sidecar.
- **Cancel**: the phone sends the existing `Cancel` envelope when the user
  starts talking during a speak; the dispatcher checks the flag before
  enqueueing and before responding.
- **Crash**: stdout EOF, non-JSON header, or id mismatch → drop the child,
  record the crash, `voice_sidecar_failed` (retryable; `false` after 3
  crashes in 60 s). The response carries the log path, not its contents.

### 4.4 Request flows

- **STATUS**: uv lookup → exact `.complete` marker + expected GGUF size →
  provisioning state → `VoiceStatus`. Answers at once; with `warm` and READY
  it also spawns the sidecar and runs `load` on a detached task (no-op if
  already hot). The phone calls it on screen open.
- **SESSION**: record or clear the voice session for `agent_id` on this
  connection (see §4.3). Inline, no sidecar involvement.
- **PROVISION**: refuse without `confirmed` (`voice_consent_required`);
  refuse while already provisioning (`voice_provisioning`, retryable);
  phase `installing_runtime` while `uv run` resolves; forward each progress
  line as `HostEvent { kind: VOICE_PROVISION, scope: "voice", voice.provision }`
  to every subscribed connection and cache it for STATUS; after `ok`, run
  `load` as the `verifying` phase so a corrupt download fails here and not
  on the first utterance; answer with `VoiceStatus` READY. Cancel → sidecar
  `cancel`, partials deleted, `cancelled`.
- **TRANSCRIBE**: validate (`audio` 1..=8 MiB, accepted mime) →
  `spawn_blocking(audio::decode_to_mono_f32)` →
  duration 200 ms..=120 s → sidecar → `text::transcript_line`: trim, map
  every control char (`\n`, `\r`, `\t` included) to a space, collapse runs.
  That is what makes the phone's `transcript + CR` through
  `OPERATION_TERMINAL_INPUT` safe; a newline would submit early in Claude's
  TUI. Empty text is `ok: true` with `transcript.text == ""` (not an error;
  nothing to retry). The host does **not** type into the pane; the phone does,
  through the existing input path with its correlation machinery.
- **SPEAK**: `text` required (replay, or arbitrary text); provider
  unspecified or `EDGE_TTS`; `voice` default `en-US-AvaNeural` else validated
  by regex → `speech_text()` (empty → `voice_nothing_to_say`) → sidecar →
  `VoiceSpeech`. The phone normally does not need it: replies arrive pushed.
- **Pushed reply**: `Stop` for a session agent → `speech_text` → sidecar →
  `EVENT_KIND_VOICE_REPLY` with `VoiceSpeech { audio, display_markdown, speech_text, truncated,
  agent_id, state_generation, reply_at }` to the session's connection only.
  Failures (network, sidecar) push the same event with empty `audio` and
  the error in `VoiceStatus.detail` so the phone can show the text and offer
  a retry via SPEAK.

### 4.5 Reply capture and speech text

- Ingest: on `Stop` with a non-empty message, call
  `VoiceService::on_agent_reply(agent_id, text, truncated, state_generation,
  occurred_at)` after the state update. Claude's "Stop while subagents run"
  (lifecycle stays Working) is skipped: only a `Stop` that lands the agent in
  `Idle` is pushed, so one turn yields one spoken reply.
- Identity promotion: after the replacement state is committed and its lock is
  released, move Voice registration from empty-native-ID records retired by
  that same event to the new non-empty native ID. Queue the Agent State event
  after this transfer and before dispatching the deferred Stop reply, so even a
  first authoritative event that is already Stop lets the phone retarget before
  a reply addressed to the new identity can arrive. A narrow ingest-order lock
  spans commit through those side effects so concurrent hook connections cannot
  publish later state first.
- Accepted overload limit: the host's bounded control-event queue keeps its
  existing overflow behavior. If that queue is already saturated at the exact
  promotion publication, Agent State can be replaced by `RESYNC_REQUIRED` and
  the active local Voice session may become unavailable. Voice adds no blocking
  send, async backpressure pipeline, retry timer, alias history, or snapshot
  inference for this exceptional condition.
- Reconnect re-registers the promoted native ID after the phone has observed the
  handoff. If the control-lane disconnect overlaps that first native event, the
  reconnect snapshot has no retired-ID relationship and cannot retarget a local
  manual-ID session. Recovering that missed relationship would require the
  rejected snapshot inference, alias history or protocol state, so this narrow
  reconnect-overlap case remains an accepted limit.
- `speech_text(markdown, 1500)`: fenced blocks (``` and ~~~) → " code
  omitted. "; inline backticks removed keeping content; headings → sentence
  with trailing period; list markers and blockquote `>` stripped; emphasis
  markers removed; `[text](url)` → text, `![alt](url)` → alt, bare URLs →
  "link"; table pipes → ", "; HTML tags and rules dropped; whitespace
  collapsed; paragraph breaks → ". " when the previous char is not terminal
  punctuation. Over the cap: cut at the last `.`/`!`/`?` + whitespace before
  it, else last whitespace; append " The rest of the reply is on screen."
  and set `truncated`.

### 4.6 Failure states the host reports

| Situation | Status / code | retryable |
| --- | --- | --- |
| uv not found | readiness `UV_MISSING`, `detail` = install hint (astral.sh installer or `MUXFLOW_UV_PATH`); transcribe/speak → `voice_uv_missing` | no |
| model absent | `MODEL_MISSING` + `model_download_bytes`; transcribe → `voice_model_missing` | no |
| provision without consent | `voice_consent_required` | no |
| provisioning already running | `PROVISIONING` with progress; `voice_provisioning` | yes |
| download/verification failed | phase `failed` + error; partials removed; `voice_provision_failed` | yes |
| sidecar crashed / bad frame / spawn failed | `detail` = summary + log path; `voice_sidecar_failed` | yes, no after 3 in 60 s |
| cold start > 120 s | `voice_sidecar_timeout` | yes |
| edge-tts network error | `voice_network_unavailable` | yes |
| audio too large / long / short / undecodable / bad mime | `voice_audio_*` | no |
| transcription empty | `ok: true`, empty text | — |
| cancelled by the phone | `cancelled` | no |
| queue full | `voice_busy` | yes |
| too many voice sessions (> 8) | `voice_too_many_sessions` | no |
| bad provider / voice / request shape | `voice_provider_unsupported` / `voice_invalid_request` | no |

### 5.2 Feature module `src/features/voice/`

Follow the terminal feature's split: route file is param plumbing, screen in
`VoiceScreen.tsx`, logic in a plain class with vitest tests beside it.

- `voiceStore.ts` — zustand vanilla store, keyed by an immutable local session
  key (normally the initial agent ID; a bounded suffix is used only if that
  deterministic ID is reused while its retired session remains live) so
  several sessions can coexist while a remote
  identity changes: `hostStatus` (mapped `VoiceStatus`), `sessions:
  Record<sessionKey, VoiceSession>` with `VoiceSession = { agentId, paneId, sessionId,
  startedAt, messages: VoiceMessage[], phase: "idle" | "recording" |
  "transcribing" | "sending" }`, `VoiceMessage = { id, kind: "you" |
  "agent", displayText, speechText, at, truncated?, fileUri?, durationMs?, played: boolean }`,
  one `playback: { messageId, state: "playing" | "paused", positionMs }`
  (a single player app-wide) and `lastError`; persisted `voiceAutoPlay`
  defaults true to preserve the original behavior.
  An authoritative same-event, pane-derived-to-native, same-adapter/same-pane identity promotion
  updates only `VoiceSession.agentId` and its route. Messages, phase, files,
  playback and the record key stay unchanged. Sessions live in memory until
  `endSession(sessionKey)` deletes their MP3
  files; they are not persisted across app restarts.
- `VoiceController.ts` — plain class like `TerminalController` (injected
  `getConnection`, `recorder`, `player`, `files`,
  `onChange`, `log`; all injectable for tests):
  - `sessionKey` is immutable local ownership; the current remote `agentId` is
    mutable. Store mutations use the former, while registration, guarded
    terminal input, availability and replies use the latter. Promotion reuses
    the recorder/player/controller and replays no utterance or reply. The host's
    transferred registration remains authoritative; only an old-ID registration
    already in flight is coalesced into one new-ID follow-up.
  - `start()`: `voiceStatus(opId, { warm: true })` → store; `voiceSession(agentId)`
    (repeated every 5 min while the session exists, including while
    backgrounded, since the SSH connection is kept alive by the existing
    foreground service; re-sent after every reconnect); `prepareToRecordAsync()`
    once so press-in only calls `record()`. The session, not the screen, owns
    the registration: leaving the screen keeps it; `endSession()` sends
    `voiceSession("")`. subscribe to agent transitions via a
    registry callback installed in `connectionManager` (`onAgentTransition`
    fan-out; notifications already consume it, add a second subscriber).
  - `beginUtterance()` / `endUtterance()` from press-in / press-out. Stop
    any playback on begin. On end: `File(recorder.uri).bytes()` →
    `voiceTranscribe(opId, bytes, "audio/mp4")` on the control connection with
    `timeoutMs: 70_000` → `utf8Encode(transcript) + CR` through
    `terminalInput(paneId, …)` exactly as `TerminalScreen.sendText` does →
    append a "you" turn. `voice_empty_transcript` → toast "Didn't catch
    that", nothing sent. Recordings under 300 ms are discarded.
  - `onVoiceReply(speech)`: from the pushed `EVENT_KIND_VOICE_REPLY`, routed
    by `speech.agentId` to that agent's session (ignored if none). Stop
    playback if it is playing that agent's previous reply, delete the
    previous file, write `new File(Paths.cache, "voice/<agentId>.mp3")`,
    append an "agent" message and set `latestReply` with `played: false`,
    `markSeenIfNeeded(agent)`. If the app is in the foreground and that
    agent's screen is focused and `voiceAutoPlay`, play it now and mark it
    played; otherwise it waits and auto-plays when the screen regains focus. Empty `audio` (host-side TTS failure) shows the original Markdown with
    a Retry that calls `voiceSpeak(speechText)` and fills in the file.
  - Playback (`player.ts`, one expo-audio player): `play()`, `pause()`,
    `resume()`, `stop()`, `seek(ms)` for the session's latest reply; status
    events update `playback.positionMs`; `beginUtterance()` stops playback. Audio mode `playsInSilentMode`,
    `interruptionMode: "duckOthers"`.
  - `endSession()`, `provision()` (progress from
    `onVoiceEvent` events updates `hostStatus`), `stop()`.
  - Recording setup: `requestRecordingPermissionsAsync()` once;
    `setAudioModeAsync({ allowsRecording: true, playsInSilentMode: true,
    interruptionMode: "duckOthers" })`; explicit preset
    `{ extension: ".m4a", sampleRate: 16000, numberOfChannels: 1, bitRate:
    48000, android: { outputFormat: "mpeg4", audioEncoder: "aac" } }`.
- `VoiceScreen.tsx` — header as in `TerminalScreen` (back, agent title,
  `StatusPill`, an "End session" action); scrolling message list: "you"
  bubbles show the transcript, "agent" bubbles show the reply text
  (collapsed to three lines, tap to expand); the newest agent reply carries
  the voice-message player in the Telegram shape — play/pause button, a
  thin position bar that is also a seek target, duration, an unplayed dot;
  status area: "uv not found on this host" card showing the
  host's `detail`, or "Set up voice · downloads ~697 MB" button with a
  progress bar, or a speaking indicator with Stop and Replay; a large
  press-and-hold mic button (pulsing ring while recording, spinner while
  transcribing, label "Hold to talk"). Disabled when not connected, agent
  `present === false`, or `hostStatus` not ready. Tokens only
  (`colors/metrics/radii/typeScale`); haptic on press-in via the existing
  `VIBRATE` permission is optional.
- Entry point: a mic glyph in the `TerminalScreen` header next to Files,
  pushing `/voice/[paneId]` with `sessionId`. Agents-list shortcuts can
  come later.
- Route `app/voice/[paneId].tsx` (param plumbing like
  `app/terminal/[paneId].tsx`); register in `app/_layout.tsx`.
