What changes

  • Untracked joins Changes. One list, as VS Code's default (git.untrackedChanges: mixed). An untracked file is marked U; a file with staged and unstaged edits shows in both groups, as today and as VS Code.
  • Group actions. Staged Changes: Unstage All. Changes: Discard All and Stage All. Merge Changes has none: staging a conflict marks it resolved, so bulk actions never touch conflicts.
  • Discard All asks once, naming both counts: files reverted and untracked files deleted. Staged changes are kept, as in VS Code.
  • Commit with nothing staged commits everything: tracked and untracked (VS Code's smart commit with smartCommitChanges: all, but without the prompt). The button says so: Commit all 6. Blocked while a conflict is open.
  • Commit & Push is first-class. Commit gets its own full-width row; Commit & Push and Push share the row below. The caret menu goes away.
  • An empty message no longer blocks. The box shows, greyed, the message the commit will get; typing replaces it.
  • The palette gets git.stageAll, git.unstageAll, git.discardAll.

Open questions

  • Push with nothing to push: the status does not carry an ahead count today, so Push stays enabled. Worth adding ahead/behind to the status to label it Push ↑2?
  • Discard All in VS Code leaves staged changes alone. Keep that, or make it discard staged too?
